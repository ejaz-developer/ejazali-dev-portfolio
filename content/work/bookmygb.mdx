## Challenge

Bus travel across Gilgit-Baltistan — Skardu, Gilgit, and Hunza — is still booked
the hard way. A passenger calls a terminal, asks whether a seat exists, and often
travels on a promise. Operators run schedules and reservations from memory or
paper, and nobody has a shared, current view of what is actually available.

The problem is not one screen. It is three people who need the same trip data
looking at it from different sides: the passenger booking a seat, the operator
running the bus, and whoever oversees the whole network.

## Approach

I split the system by role instead of by feature, because that is how booking
actually fails — handoffs between people, not missing buttons.

- **Passenger** — find a route, see open seats, reserve one, and hold a ticket.
- **Operator** — publish schedules and manage the reservations on them.
- **Super-admin** — oversee operators, routes, and the overall network.

The booking flow is the spine. Everything else hangs off the same trip record so
a seat reserved by a passenger is the same seat an operator sees as taken.

## What I built

- Route discovery across the northern terminals.
- A seat-selection booking flow with reservation handling.
- Operator tools for schedules and reservations.
- A super-admin layer for overseeing operators and routes.

## Stack

- **React** with **Redux** for the booking interface and shared trip state.
- **Node.js** and **Express** for the API and booking rules.
- **MongoDB** for routes, schedules, trips, and reservations.

## Result & status

BookMyGB is **in development**. The booking interface is deployed and the three
role areas are being built out. The landing page currently reports zero operators
live and zero seats open because no operator data has been seeded yet — that is
the real state of the product, not a launch figure. The next step is seeding
demo data and opening the operator and passenger flows for a full review.
